# Further Rust import stages

The direction is to move substantial import pipelines into Rust, so JavaScript makes one call per batch or operation. The current batch Source validator/persister establishes that boundary. The user authorized broader conversion wherever it helps, with an eventual Rust implementation as the direction. All work continues from `rust-object-import`; preserve the original `rust` branch.

1. **Batch decompression for metadata objects — complete.** [PR #36](https://github.com/zkochan/bit/pull/36) is merged, with all 17 runnable CI checks passing. Bounded lossless UTF-8 metadata inflation runs in Rust; model hydration, merge policy and persistence remain canonical Node operations. See [metadata-results.md](./metadata-results.md) for file/HTTP readback qualification and callback/elapsed-time measurements.

2. **Object-store inventory and batched reads — existence checks and bounded reads/header classification merged.** Large stateless existence batches now run in Rust with real artifact-import qualification; see [inventory-results.md](./inventory-results.md). Read/header qualification is in [read-results.md](./read-results.md). Bounded directory traversal and combined classification are implemented and qualified; see [traversal-results.md](./traversal-results.md). Larger native streaming reads remain future work. Group existence checks, directory traversal, compressed-header classification and hash/content verification in Rust. Keep oversized Source content streaming; compare on both tmpfs and ordinary local disk. Preserve unreadable-object reporting, transformer hooks, permissions, cache identity and concurrent-file-change behavior. Measure warm commands as well as imports before adding a long-lived cache.
3. **Native mutable persistence and merge kernels — small post-policy compression/persistence implemented.** The importer retains canonical Version/VersionHistory/LaneHistory policies, makes VersionHistory merging linear, and moves eligible compression/atomic writes into a persistent Rust session. See [mutable-results.md](./mutable-results.md); larger metadata remains on Node after a measured regression. Next, port Version, VersionHistory and LaneHistory merging with differential fixtures for parents, graph completeness, scope changes, duplicate histories and conflict/error policy. Port component merging and index construction once those primitives preserve the canonical behavior. Let Rust return a completed operation summary; avoid a callback to Node for every object or merge decision. Extension hooks need an explicit operation boundary and compatibility path.
4. **Tar-stream intake.** Move framing, entry traversal, Source validation and persistence together. Keep the existing authenticated HTTP client initially, feeding bounded chunks to Rust. Preserve `.BIT.START`/`.BIT.END`/`.BIT.ERROR`, schema handling, missing-end and truncated-tar errors, unknown members, cancellation and remote-error attribution. Buffer or spool bounded batches until JavaScript has made any required policy decisions; never acknowledge an incomplete import as complete. Qualify against Bit's original encoder/decoder and actual loopback HTTP route before deployment network tests.
5. **Distribution and platform qualification.** Package the object-import helper with source/runtime identity, target/ABI/license checks, integrity verification, atomic installation and rollback. Extend native metadata/rename behavior to Windows with real OS tests. Continue the exact pnpm Rust formatting/lint configuration. Keep generated archives, JSON, profiles and logs outside the source repository.
6. **Operation-level orchestration.** Once the kernels above are compatible, move queueing, index transactions and cacheable native state behind a Rust import operation. Compare complete user commands, not only native kernels. Extend beyond import to hashing, object traversal and component loading when the same operation boundaries reduce callbacks and improve measured command performance.

For every stage, commit small reviewable changes, target PRs to `rust-object-import`, preserve repository readback and canonical errors, and report whole-client CPU/memory including the helper. The existing five-mode command harness supplies the baseline. Native rollout stays opt-in until the broader workload/platform results justify the default; improving local processing does not remove network waiting.

## Object-store implementation sequence

Bounded existence checks and compressed reads/header classification are merged and qualified. Native small-metadata compression/persistence is implemented and qualified after canonical Version/history merge decisions; see [mutable-results.md](./mutable-results.md). VersionHistory merging is now linear in Node. Native merge policy, component/index transactions and larger operation boundaries remain future work. The first four steps below are implemented, and step five now has a bounded read/header implementation; bounded directory traversal is also implemented and qualified. Larger streaming reads remain. `Repository.hasMultiple()` batches large groups in Rust; inventory callers can group those checks without returning large object contents. Keep the first implementation stateless so concurrent writes remain visible and no new cache invalidation policy is introduced.

1. Trace the import inventory callers and preserve ordering, duplicate handling, in-memory pending objects and canonical missing/unreadable-object behavior.
2. Add a bounded native request accepting only validated object hashes under the configured repository root. Return ordered existence results; retain Node fallback for unsupported platforms, hooks, protocol errors and helper failure.
3. Integrate at callers that already have a batch, preserving the scalar API for isolated lookups. Avoid adding one helper call per object.
4. Differentially check missing/existing objects, pending objects, permissions, concurrent create/delete and crash fallback. Measure cold and warm object-only commands on tmpfs and ordinary disk, including total helper CPU/RSS and filesystem callback counts.
5. Extend to bounded reads/header classification only after the existence batch is qualified; retain streaming for large Source content and canonical hydration/cache identities.
